## 0. 结论摘要

| Freqtrade 阶段 | 核心价值 | 可移植度 | 判断 |
|---|---|---|---|
| 数据下载 Data Downloading | 数据与策略解耦、增量补齐、可复现契约 | ★★☆ | **建，但不能照搬**——A股要额外的复权/停牌/财报公告日/退市快照 |
| 回测 Backtesting | 把"K 线内不可知"显式假设化；结果可复现 | ★★☆ | **重写**——A股 T+1、涨跌停、整手、印花税让它的撮合假设整体失效 |
| 超参搜索 Hyperopt | optuna 空间化搜索 + 12 个内置目标函数 | ★★★ | **可直接搬方法论**，这是投入产出比最高的一块 |
| 偏差自检 Lookahead / Recursive | 不改策略代码即可反证前视偏差与指标预热不足 | ★★★★ | **最该抄的一块**，几乎零成本、且是回报可信度的地基 |

一句话：**Freqtrade 的四个阶段里，真正值得"抄"的是偏差自检的方法论；回测内核必须重写；数据层要自己建（point-in-time 是最大的坑）；超参搜索那套可以直接用。**

**它不会白送给你的东西**：基准对照（加密没有沪深300/标普这种基准概念）、可成交性模型（加密 7×24 连续报价没有涨跌停与停牌）、以及任何因子——Freqtrade 的因子全在策略文件里由开发者自写。

> **盘点后的现实（决定了本文的性质）**：本项目引擎目前是"**实时选股 + 组合优化**"，**不是"历史回测"**——行情零落盘、`latest-<market>.json` 只留最新、唯一的回测函数只被测试调用且没有任何入口、涨跌停参数写了但全仓无人消费。
> 所以这份文档不是"把 Freqtrade 的改进搬过来"，而是"**从零建研究底座，并在第一天就把 Freqtrade 花了很多年才补齐的两样东西（可复现数据契约 + 偏差自检）设计进去**"。盘点细节与证据见 §7。

## 1. Freqtrade 研究闭环逐阶段拆解

### 1.1 数据下载：一份"可复现的数据契约"

**做法**：`freqtrade download-data` 把历史 K 线**落盘成按 pair×timeframe 组织的本地文件**，回测/超参只读本地、不再打交易所。

| 设计点 | 官方行为 | 为什么重要 |
|---|---|---|
| 存储格式 | 默认 `feather`（Apache Arrow）；可选 json / jsongz / parquet；由 `dataformat_ohlcv` / `dataformat_trades` 配置 | 官方给了性能/体积对照（feather 115MB/1.6s 那档最优），并支持 `convert-data` 互转 |
| 增量下载 | 若本地已有数据，**自动算出缺失区间**，只补缺（`--days` 或 `--timerange` 均可省略） | 这是"数据契约"的核心：每天定时补齐，回测永远读完整本地快照 |
| 补历史 | `--prepend --timerange <end>` 往前扩数据 | 扩展回测区间不需重下 |
| 可核对 | `freqtrade list-data --show-timerange` | 跑回测前先确认数据覆盖度 |
| 缺失 K 线 | 官方 FAQ：交易所没返回的 K 线会被填成"空 K 线"（OHLC 全等于前一根收盘价、volume 为空） | 避免指标在缺口上算出错误值 |
| 期货附加数据 | 自动补 `mark` 与 `funding_rate` 蜡烛（funding_rate 用 `date`+`funding_rate` 两列） | 现货没有，属于市场结构差异 |
| tick 级 | `--dl-trades`（Kraken），可将 trades 转 OHLCV | 不同交易所数据可得性差异的处理范式 |

**值得抄的心智模型**：数据是**独立可复现资产**，不是"回测时去拉一下"的副作用。回测报告 zip 里连 market change 的 feather 都带上（见 1.2），保证"同一份数据 + 同一份策略 + 同一份配置 = 同一份结论"。

### 1.2 回测：把"不可知"显式假设化

**执行结构**（`bot-basics.md`）：加载本地数据 → `populate_indicators()` 每 pair 一次 → `populate_entry_trend()` / `populate_exit_trend()` 每 pair 一次 → **逐 K 线循环**模拟入场与出场，每根 K 线内按顺序跑回调。

**官方明说的 8 条假设**（`backtesting.md:556-589`，择要对本主题最关键的）：

1. 入场按开盘价，除非实现了自定义价格逻辑；
2. **无滑点**：只要价格落在 K 线高低区间内就按请求价全额成交；
3. 出场信号按**下一根 K 线的开盘价**成交；
4. **同一根 K 线内 Stoploss 先于 ROI** 判定（官方直言：所以回测里 stoploss 出场会明显多于 dry-run）；
5. **低点先于高点**（"protecting capital first"），且 **exit-signal 优先于 stoploss**（假设信号在开盘触发）；
6. ROI 以 high 比较但按 ROI 值成交，且"永不低于 K 线"；
7. 尊重交易所最小/最大下单量与最小名义金额；
8. 兜底句：**"backtesting will never replace running a strategy in dry-run mode."**

**提高精度的手段**：`--timeframe-detail 5m`（在 1h 回测里用 5m 近似日内路径；必须小于主 timeframe）。文档里给了一个直观例子：同一个 10:00 信号在不同 `max_open_trades` 下的成交顺序差异。

**可复现与工程细节**：

| 机制 | 说明 | 坑 |
|---|---|---|
| 报告 zip | 含 json 报告 + market change feather + **策略文件副本** + 参数文件副本 + **脱敏 config** | 不含依赖模块，所以环境变了结论仍可能变 |
| 结果缓存 | 默认复用 1 天内的相同回测结果（`--cache none` 强制重算） | 官方警告：**会静默忽略策略 import 的模块改动** |
| 动态 pairlist | 使用非 StaticPairlist 时**回测不可复现** | 官方建议先 `test-pairlist` 固化成静态名单再回测 |
| 结果切片 | enter tag / exit reason / mix tags 三张归因表；`--breakdown day week month year` | 这是"为什么赚钱"的第一层归因 |
| 深挖 | `--export trades` 导出逐笔后用 pandas / Jupyter；webserver 模式可视化（可加载历史结果、支持 `--notes`） | 归因能力远超"看一个总收益" |

### 1.3 超参搜索：把"参数"变成"可搜索空间"

**引擎**：optuna，当前采样器 `NSGAIIISampler`；先跑 30 个随机初始点（输出里带 `*` 标记）再进入模型引导搜索。

| 维度 | 官方设计 |
|---|---|
| 搜索空间定义 | 参数写在策略类里：`IntParameter` / `DecimalParameter` / `CategoricalParameter` / `BooleanParameter`，用 `space='buy'/'sell'/'enter'/'exit'/'protection'/自定义名` 分组；`--spaces roi stoploss trailing` 等按组开关 |
| 内置超空间 | `roi`（自适应 4 行 ROI 表，范围随时 timeframe 变）、`stoploss`（默认 -0.35…-0.02）、`trailing`（默认不含，官方建议单跑） |
| 目标函数 | **12 个内置 loss**：ShortTradeDur（默认）、OnlyProfit、Sharpe、SharpeDaily、Sortino、SortinoDaily、MaxDrawDown、MaxDrawDownRelative、MaxDrawDownPerPair、Calmar、ProfitDrawDown、MultiMetric（收益+回撤+盈亏比+期望+胜率，并对低交易数罚分）；支持自定义 |
| 精度限制 | 小数统一限 3 位，官方理由：**"more precise than this will usually result in overfitted results"** |
| 收敛控制 | `--early-stop N`（0=关闭，官方建议取总轮数的 20-30%，小于 20 会被抬到 20） |
| 并行 | `-j` 多进程；`--analyze-per-epoch` 处理"参数进了指标计算"的场景（与 `.range` 的区别是文档里专门讲的一节） |
| 复现 | `--random-state`；未指定时日志会打印本次随机种子供复用 |
| 结果管理 | 落盘 + **自动把最优参数写回策略文件**（`--disable-param-export` 关闭）；`hyperopt-list` / `hyperopt-show` 事后筛选与查看 |
| 自检 | 专章 "Validate backtesting results"：解释为什么超参结果与回测不一致（protections 开关不一致、pairlist 动态、缓存…） |

**结论**：这一层是纯工程 + 统计方法论，与市场无关，**可以整体搬到 A股/港美股/ETF 上**——只要你有"可跑的向量化回测 + 一个标量目标函数"。

### 1.4 偏差自检：最该抄的一块

这是 Freqtrade 相对多数自研系统真正领先的地方——**它把"你的结论可能是假的"做成了两个可执行命令**。

#### `lookahead-analysis`（前视偏差反证）

- **原理**：不看策略代码，而是**跑基线回测 → 对每个入场/出场信号单独用"只含该 pair 的名单"重跑 → 对比指标值与信号位置是否变化**。变了就说明这个信号"看到了未来"。
- **强制参数**（全为压制假阳性）：`--cache none`、`--max-open-trades ≥ pair 数`、钱包设为无限（10 亿）、固定 stake 10000、**关闭 protections**、`order_types` 强制 market。
- **产出表**：`has_bias`（No 好 / Yes 坏）、`total_signals`、`biased_entry_signals`、`biased_exit_signals`、`biased_indicators`。
- **官方列出的典型前视写法**（可直接当 code review 清单）：
  - `shift(-10)` 往后看；
  - 在 `populate_*` 里用 `iloc[]` 取特定行；
  - 循环（for-loop）控制不严时引入未来信息；
  - **`.mean()/.min()/.max()` 不带滚动窗口 = 在全表上算**，信号所在的 K 线"看得到"未来；正确写法是 `rolling(12).mean()`；
  - `ta.MACD(..., signalperiod=1)` 这类参数会引入偏差。
- **官方自己承认的 5 类 caveat**（说明这个工具不是银弹）：
  1. 只验证**实际触发过**的信号，没触发的会假阴性；
  2. 单 pair 重跑假设"单 pair 行为 = 全名单行为"，**策略若依赖跨 pair 排序（如按波动率排名选币）会被误报为有偏差**——这条对本项目特别相关，因为选股天生是横截面排序；
  3. 限价单 + `custom_entry_price` 会造成假阳性，所以强制市价；
  4. FreqAI 的 target 指标会被误标；
  5. 假阳性可能出现在出场信号上（入场有偏往往连带出场有偏）——官方建议"**先修入场，再修出场**"。

#### `recursive-analysis`（指标预热/递归偏差）

- **原理**：把同一段历史切成**不同长度**分别计算指标，比较**最后一根 K 线**上指标值的方差 → 判断 `startup_candle_count` 是否足够。
- **为什么重要**：递归型指标（EMA、RSI…）用 1000 根还是 500 根算出今天的值是不同的（文档用 `steps` 递推做了直观例子）。回测拿到的是全量数据，实盘只拿到交易所给的有限根数，**两者的指标值不一致 → 回测结论不可移植到实盘**。
- **产出**：不同 `startup_candle_count` 下的方差百分比表；`nan%` 表示数据不够算不出；目标是"方差足够小"，**不是追求零**（零往往需要不现实的长窗口）。
- **附带能力**：同一命令顺带做**指标级的**前视检查（完整的信号级检查仍需 lookahead-analysis）。
- **已知限制**：只查 `populate_indicators` 与 `@informative`，写在 `populate_entry_trend/exit_trend` 里的指标不会被检查；只比较最后一行的值。

> 两个命令都能通过 REST（webserver 模式）作为后台任务触发，且**同一时刻只允许跑一个**。

## 2. 映射到 A股 / 港股 / 美股 / ETF

### 2.1 先说为什么不能照搬：七个结构性差异

| 维度 | 加密（Freqtrade 原生） | A股 | 港股 | 美股 | 对本项目研究闭环的影响 |
|---|---|---|---|---|---|
| 交易时段 | 7×24 连续 | 4 小时（9:30–11:30 / 13:00–15:00）+ 集合竞价 | 5.5 小时 | 6.5 小时 + 盘前盘后 | "K 线内路径不可知"在 A股更严重：隔夜跳空 + T+1 双重放大 |
| 价格约束 | 无涨跌停 | 主板 ±10%、创业板/科创板 ±20%、北交所 ±30%、风险警示股见 §2.3 | 无涨跌停（有市调机制） | 个股/全市场熔断 | **"无滑点、区间内必成交"直接失效**：一字板买不进、跌停卖不出 |
| 回转交易 | 即时（现货） | T+1（股票）；部分 ETF 支持 T+0 | T+0 | T+0（资金 T+1） | 出场优先级表要追加"当日买入不可卖"约束 |
| 最小单位 | 任意小数 | 100 股整手（科创板 200 股起、1 股递增；北交所 100 股起、1 股递增） | 每手不同（100/200/500/1000…） | 1 股 | 仓位计算需二次取整，取整残差会累积 |
| 公司行为 | 基本没有 | 分红/送转/拆股 → **复权** | 同 | 拆股/分红 | A股回测第一大坑，详见 §3.1 |
| 基本面数据 | 无 | 财报有"**报告期 vs 公告日**" | 同 | 10-Q/10-K 有明确 filing date | point-in-time 的最大来源 |
| 标的存续 | 币种长期存在 | ST / 退市 / 长期停牌 / 更名 | 同 | 同 | 幸存者偏差，直接影响选股结论 |
| 成本结构 | maker/taker 手续费 | 印花税（卖出单边）+ 过户费 + 经手费 + 证管费 + 佣金（含最低 5 元惯例） | 印花税（双边）+ 交易费 + 交易征费 + 结算费 | 佣金（多已 0）+ SEC fee（卖出）+ TAF（卖出） | 决定"毛收益能否覆盖摩擦"，尤其对高换手策略 |

> 费率具体数值请以交易所/中国结算最新公告为准（本表刻意只列**成本科目**，不列小数位）；本项目 `config/` 里已有市场规则配置，映射时应复用引擎现有参数，而不是在回测里重新硬编码一套。

### 2.2 逐阶段映射表

| Freqtrade 机制 | 本项目对应物 / 需要什么 | 可移植度 | 关键改造 |
|---|---|---|---|

| 缺失 K 线填"空 K 线" | 停牌日同样需要占位处理 | ★★★ | 停牌 ≠ 无数据：要么占位、要么显式剔除并记录原因 |

| 8 条回测假设显式化 | 换成 A股版假设表（见 §3.2） | ★★★★ | **方法论直接抄**：先写清假设，再谈结论 |
| 报告 zip（含策略/配置/市场变化数据副本） | 每次评估产出**可复现包**（数据快照 id + 因子配置 + 权重 + 结果） | ★★★ | 这是"结论可审计"的工程基础，与本项目"证据链"理念一致 |
| `--breakdown day/week/month/year` + enter/exit tag 归因 | 按**因子贡献 / 行业 / 市值分组 / 持有周期**归因 | ★★★ | 归因维度要本地化：本项目应按六因子与市场分组，而非按 enter_tag |
| `--export trades` 后用 pandas/Jupyter 深挖 | 逐笔明细落盘（CSV/Parquet）+ 分析脚本 | ★★★ | 低成本高回报 |
| hyperopt + optuna + 12 个 loss | 对**六因子权重、硬筛选阈值、风控参数**做空间化搜索 | ★★★ | 见 §3.3：这是投入产出比最高的一块 |
| `.range` / `--analyze-per-epoch` 的取舍 | 本项目因子计算不进搜索循环（因子是确定性的），所以**没有这个问题** | — | 本项目结构上更简单，直接全量重算即可 |
| lookahead-analysis（切片重跑反证） | 需要"**同一天用不同信息集重算，比较信号是否变化**"的能力 | ★★★★ | 横截面排序策略要用**留一法**变体，见 §3.4 |
| recursive-analysis（不同长度比最后一根） | 需要"因子预热窗口敏感性"检查 | ★★★★ | 直接可用：按不同预热窗口重算，比较当日因子值方差 |
| 一个 pair 一个持仓 | 与"单票上限"约束相容 | ★★★ | 可保留 |

### 2.3 2026-07-06 A股交易新规：四个必须进"数据契约"的后果

这不是背景知识——它直接改变回测的合法性。已核实的新规要点（[证监会上海监管局转载证券日报](https://www.csrc.gov.cn/shanghai/c105566/c7643909/content.shtml)、[中国证券报](https://m.cnfin.com/gs-lb//zixun/20260708/4437089_1.html)）：

1. **主板风险警示股（ST/*ST）涨跌幅由 5% 放宽到 10%**；创业板/科创板风险警示股维持 20%，北交所维持 30%。
2. **盘后固定价格交易从科创板/创业板扩展到全部 A股 + ETF**：15:05–15:30 按**时间优先**撮合，**以当日收盘价成交**；上交所接受申报时间 9:30–11:30、13:00–15:30，深交所 9:15–11:30、13:00–15:30。北交所亦拟推出。
3. **沪市基金（ETF/LOF/REITs）14:57–15:00 由连续竞价改为收盘集合竞价**，最后 3 分钟只能限价申报且**不可撤单**；深市基金原本已是集合竞价。
4. 深交所创业板引入做市商制度；北交所对风险警示股设当日累计买入 ≤20 万股上限。

**对研究闭环的四个直接后果**：

| 后果 | 说明 | 对应改造 |
|---|---|---|
| **① 撮合规则有了"版本"** | 同一个策略在 2026-07-05 与 2026-07-06 面临不同的涨跌幅约束 | 回测必须带**规则版本**维度；跨规则变更点的长周期回测 = 把两个不同市场拼接，和跨市场拼接一样是伪结论来源 |
| **② 执行通道多了一条** | 盘后固定价格交易 = 用当日收盘价成交，且**没有盘中冲击成本** | 回测应支持三种执行假设：次日开盘 / 次日 VWAP / **当日盘后固定价格（收盘价）**——这条对本项目"日频信号"尤其友好 |
| **③ 但新通道流动性很薄** | 新规首日 A股 ETF 盘后成交额仅 0.56 亿元，**平均每笔 0.8 万元** | 盘后通道在回测里应建模为"小额可成交、大额不可依赖"；不能假设无限深度 |
| **④ 历史有效策略会被规则杀死** | 依赖"沪市基金尾盘连续竞价"的抢尾盘/折溢价套利策略，因改为集合竞价而系统性失效 | 回测结论必须标注"在该规则版本下有效"；**这正是 Freqtrade 闭环里没有的概念**（加密规则稳定），也是移植时最容易被忽略的一等公民 |

> 一句话：**Freqtrade 的闭环缺"规则版本"这一维，因为加密市场不需要；A股必须有。** 这是本文档最重要的结论之一。

## 3. 必须补齐的四块能力

### 3.1 Point-in-time 数据层（P0，最大风险源）

加密市场不存在这个问题：币不会发财报、不会分红、不会退市、不会被 ST。A股研究结论不可信的头号原因就是**用了当时拿不到的数据**。

| 数据项 | 陷阱 | 正确做法 |
|---|---|---|
| **复权** | 前复权序列用"今天"的复权因子重算全部历史 → 历史价格水平与当时可交易价格不符。用于收益率计算尚可，但**用于涨跌停判定、整手取整、价格阈值过滤会系统性失真** | 存**不复权价 + 复权因子**两套；信号用复权算，撮合/过滤用不复权价算 |
| **财务数据** | 用"报告期"对齐（如 2024Q1 数据从 2024-01-01 开始可见）→ 实际要到公告日（可能 4 月底）才公开 | 全部按**公告日**（filing date）对齐；缺公告日就按最保守的法定披露截止日 |
| **成分股 / 退市** | 用"今天的沪深300成分"回测 2020 → 幸存者偏差，结论系统性偏乐观 | 存**历史成分股快照**；退市股必须留在池子里 |
| **ST / 停牌状态** | 用"今天的名称"过滤 ST → 当时不是 ST 的股票被错误剔除（反之亦然） | 存**逐日状态快照**（ST 标记、停牌标记、涨跌停价） |
| **规则版本** | 2026-07-06 新规改变了 ST 涨跌幅与收盘定价机制（§2.3） | 规则参数带**生效日期**，回测按日期取版本 |
| **快照身份** | 数据被增量更新后，昨天的回测无法复现 | 每次评估记录 `snapshot_id` + 生成时间 + 覆盖度报告 |

**验收标准**：任取一个历史日期，能一键重建"当时可见的信息集"并重算因子值，且与当时落盘的结果逐位一致。

### 3.2 可成交性模型（P1）

Freqtrade 的"无滑点、区间内必成交"在 A股 会系统性高估收益。需要显式建模：

| 规则 | 建模要求 |
|---|---|
| **涨跌停** | 一字板（开=高=低=收=涨停价）→ 买入信号**不可成交**；跌停 → 卖出**不可成交**。回测必须能"信号发出但委托失败"，并把这个失败计入统计 |
| **停牌** | 停牌日不可交易，持仓需按停牌价计入净值 |
| **T+1** | 当日买入的批次当日不可卖 —— 出场判定要先检查批次可卖量 |
| **整手** | A股 100 股（科创 200 股起）、港股按每手、ETF 100 份；下单量向下取整，**取整残差要计入现金** |
| **费用** | 印花税（卖出单边）、过户费（双向）、经手费 + 证管费、佣金（含最低 5 元惯例）；港股另有交易费/交易征费/结算费；美股 SEC fee + TAF 仅卖出 |
| **滑点** | 不能是常数：应随"委托金额 / 当日成交额"分档（如 <1%、1–5%、>5% 三档），并用 `--timeframe-detail` 式的更细粒度数据校准 |
| **执行通道** | 三选一并声明：次日开盘 / 次日 VWAP / **当日盘后固定价格（收盘价，注意流动性薄，见 §2.3）** |

**验收标准**：回测报告里必须单列"**信号不可成交率**"与"取整/费用/滑点合计摩擦占比"两项——它们是把"回测漂亮"翻译成"实盘可能"的关键。

### 3.3 评估与归因（P1）

| 需要的东西 | 说明 | 对齐 Freqtrade 的 |
|---|---|---|
| 基础指标 | 总收益、年化、最大回撤、Calmar、Sharpe、胜率、盈亏比、平均持仓周期、换手率 | `backtesting` 的 Summary metrics |
| **基准对照** | 沪深300 / 中证500 / 中证1000 / 恒生 / 标普500 / 对应 ETF —— **加密没有基准概念，这块必须自己补** | 无 |
| 归因维度 | 按**六因子贡献**、行业、市值分组、持有周期、市场分组 | enter tag / exit reason / mix tags 表 |
| 时间切片 | 日/周/月/年分解 | `--breakdown` |
| 逐笔明细 | 落盘 CSV/Parquet + 分析脚本 | `--export trades` + pandas/Jupyter |
| 可复现包 | 数据快照 id + 因子配置 + 权重版本 + 结果 | 回测报告 zip |

**验收标准**：报告必须能回答"这波收益来自哪个因子、哪个市场、哪个行业"，而不是只给一个总收益；同时必须给出基准对照与超额收益。

### 3.4 偏差自检的**横截面变体**（P3，但方法论现在就该定）

Freqtrade 的 `lookahead-analysis` 靠"**单 pair 重跑**"来反证前视偏差。**这招对本项目直接失效**——因为本项目的选股本质是**横截面排序**（按分位打分取前 N），单标的切片必然改变排序。官方文档自己也承认这类策略会被误报（`lookahead-analysis.md` caveat 第 2 条：依赖跨 pair 排序的策略会被误判为有偏）。

所以必须改成三个本地化检验：

| 检验 | 做法 | 能抓出什么 |
|---|---|---|
| **留一法（leave-one-out）** | 从当日样本中逐个/批量移除标的，看目标标的得分分位是否发生符号级变化 | 排序是否被少数标的绑架（脆弱性） |
| **未来剥离法** | 把 t 时刻之后的数据整体删除后重算因子，比较 t 时刻因子值 | **最直接的"是否偷看未来"检验**，可完全替代切片重跑 |
| **公告日对齐检验** | 把财务数据从"报告期对齐"改成"公告日对齐"再跑一遍，比较结论差异 | 量化 point-in-time 违规的影响幅度 |

`recursive-analysis` 的思路则可**直接照搬**：按不同预热窗口重算因子，比较最新一期的因子值方差，据此确定每个因子的最小预热长度（动量看 20 日、趋势看 60 日、波动率看 N 日…）。

**验收标准**：对任一策略/因子组合，能输出 `has_bias` 结论 + 偏差信号清单 + 预热窗口敏感性表。

## 4. 不建议照搬的部分

| 不建议照搬 | 理由 |
|---|---|
| **动态 pairlist**（VolumePairList 等自动选币） | 官方自己承认"非 StaticPairlist 时回测不可复现"；本项目已有确定性硬筛选 + 六因子，引入动态名单会同时破坏可复现性与可解释性 |
| **`minimal_roi` 时间衰减表** | 它是"分钟级持仓时长 → 目标收益"的映射；在日频 + T+1 + 涨跌停的市场里退化成常数，且与"止损止盈优先于 AI"的现有设计重叠 |
| **追踪止损的连续报价假设** | 加密 7×24 无跳空，追踪止损按 K 线 low 触发是合理的；A股隔夜跳空会让实盘成交价远差于回测触发价 → 回测系统性乐观 |
| **"exit-signal 优先于 stoploss"** | Freqtrade 假设信号在开盘触发所以优先；A股应取**相反**的保守口径（止损优先），否则回测会高估 |
| **无滑点假设** | 见 §3.2；必须换成分档滑点模型 |
| **加密特有的空头/杠杆/资金费率** | 本项目不涉及；引入只会增加复杂度 |
| **直接上 FreqAI 式 ML 黑箱** | 与本项目"结论必须引用证据、可解释可审计"的产品承诺冲突。可作为 P3 之外的独立探索，但不进主链路 |
| **"单笔 stake 均分"的仓位语义** | 本项目是组合级约束（单票上限/单轮换手/现金储备/目标总仓位），语义不同，不能用它的公式 |

## 5. 落地路线（P0 → P3）

| 阶段 | 做什么 | 产出物 | 验收标准 |
|---|---|---|---|
| **P0** 数据契约 | 数据快照 id + 覆盖度自检；补齐复权/停牌/涨跌停/ST/公告日/成分股/规则版本 | `data-check` 能力 + 快照清单 | 任取历史日期可重建当日可见信息集，重算结果逐位一致 |
| **P1** 评估内核 | 日频事件式撮合；A股版假设表；§3.2 全部规则；摩擦指标 | 可跑的 backtest + 逐笔明细 + 假设表文档 | 与现有纸面撮合在同一段行情、同一批决策上逐笔成交与余额一致（差异可解释） |
| **P2** 归因 + 超参 | 指标 + 基准对照 + 因子/行业/市场归因；optuna 搜索六因子权重/阈值/风控参数；walk-forward | 评估报告 + 最优参数 + 样本外报告 | 报告能回答"收益来自哪个因子"；样本外表现单独出报告 |
| **P3** 偏差自检 | §3.4 三个横截面检验 + 预热窗口敏感性 + 规则版本标注 | `has_bias` 结论 + 偏差清单 + 敏感性表 | 能给任意策略输出偏差自检结论，并在报告中标注规则版本 |

**顺序理由**：P0 不做，P1 的结论不可信；P1 不做，P2 没有目标函数可优化；P3 最容易被跳过，但它决定前三个阶段的成果是否成立——**Freqtrade 把它做成了独立命令，本项目也应该把它做成独立关卡，而不是"写在文档里的注意事项"。**

**各阶段的真实起点（据 §7 盘点）**：

| 阶段 | 起点 | 已有可复用 | 说明 |
|---|---|---|---|
| P0 | **从零** | `config/market/*.yaml`（规则版本化的落点）、调度与 catch-up 骨架 | 当前行情零落盘，历史接口只有"末 N 根"且固定 qfq |
| P1 | **改造** | `engine/research/backtest.py` 的 NAV/指标口径、`broker.py` 的 T+1 批次与费用引擎、`risk.py` 的整手取整 | 缺的是**对外入口**与**真实约束**（涨跌停/停牌/过户费/最低佣金） |
| P2 | **引入** | `engine/optimizer/`（压力测试、成本感知再平衡）属组合层，可复用 | optuna 与 loss 体系需新引入；组合采样当前无随机种子 → 不可复现，需一并修 |
| P3 | **从零** | 无 | 但方法论已在 §3.4 定好（留一法 / 未来剥离法 / 公告日对齐检验 / 预热窗口敏感性） |

## 7. 现状对照（只读代码盘点，2026-10-03）

### 7.1 一句话结论

引擎现有的研究侧是 **"实时选股 + 组合优化"**，不是 **"历史回测"**：**没有本地行情库、没有 point-in-time 数据、唯一的回测函数没有任何对外入口。**

### 7.2 差距表（vs Freqtrade 四阶段）

| Freqtrade 阶段 | 本项目现状 | 缺的具体是什么 |
|---|---|---|
| **Data Downloading** | **部分** | 有实时行情与日/周/月线拉取，但**一次性内存态、零落盘**：无本地库（SQLite/Parquet/CSV 全无）、无日期区间下载、无分钟线；历史记录只有 `date/open/close/high/low/volume` 六字段——**无成交额、无复权因子、无停牌标记、无涨跌停价**；基本面仅美股 Finnhub 快照，**无报告期/公告日 → 无 PIT** |
| **Backtesting** | **部分（有函数无入口）** | 唯一实现是 `run_rule_backtest`（5 日动量等权、T+1、固定成本 0.00225，输出年化/回撤/夏普）；**全仓检索确认它只被 tests 调用，无 API/CLI/工具入口**；无逐笔统计/胜率、无多策略、无策略 hook、无 walk-forward |
| **Hyperopt** | **缺失** | 只有组合权重的随机采样搜索（`max_sharpe(samples=3000)`，`random.expovariate` **无随机种子 → 不可复现**）+ 风险平价 + 压力测试；**无搜索空间定义、无 loss 函数、无采样器、无结果索引** |
| **Lookahead / Recursive** | **缺失** | 零实现；更糟的是数据层固定消费 **qfq 前复权序列**，本身就是未来信息的载体，且没有复权因子可还原原始价 |

### 7.3 三个最高风险点（按"会让结论不可信"排序）

**① 前复权序列被当作历史真相**

- 证据：`scripts/stock-fetcher.js:864-865`（`history` 命令固定传 `1023, "qfq"`）、`engine/research/backtest.py:5`（自述用 Tencent K 线 qfq）、`engine/research/backtest.py:19-38`、`engine/optimizer/runner.py:145` 直接消费它。
- 机制：前复权用**最新的**复权因子重算全部历史。于是 ① 历史价格水平 ≠ 当时可交易价格（对 `min_price` 这类阈值过滤、涨跌停判定、整手取整、价格精度全部失真）；② **每发生一次除权除息，整条历史被重算**，昨天算出的因子值与今天算出的不再是同一份数据 → 破坏可复现性。
- 后果：所有历史统计（动量、波动率、相关性、夏普）都带系统性偏差，且无法回溯"当时可见的价格"。

**② 没有 point-in-time 基本面，也没有历史股票池**

- 证据：`engine/screening/engine.py:393-395` 用**当前** PE/PB 打分；`engine/data/research.py:202-205` 基本面仅美股且无报告期；筛选快照只有 `latest-<market>.json`（**整体覆盖写**，`engine/screening/engine.py:21,194,442,580`）；Mongo 侧 `screening_runs` 虽按时间戳留存审计（`storage.py:242-262`），但快照与因子表是按 `(market,symbol)` **upsert 只留最新**（`storage.py:197-240`），没有按日期读取的接口。
- 后果：用今天的估值、今天的成分股去评估历史选股 = **幸存者偏差 + 财报前视**，而且**无法复现"当时到底选出了什么"**。

**③ 回测链路孤立，且与撮合层的约束不一致**

- 证据：回测无入口（`grep run_rule_backtest` 仅命中 `engine/research/__init__.py:8` 与 `tests/test_backtest.py`）；成交用 close 且成本写死 `cost_rate=0.00225`（`backtest.py:70,109`）；停牌用前值 forward-fill（`backtest.py:57-58`）。而纸面撮合走市场费率 + 滑点 + 整手 + T+1 批次（`engine/trading/broker.py`、`engine/trading/risk.py`）。
- **最刺眼的一处**：`price_limit_pct`（cn/etf=10）**只出现在 4 个 `config/market/*.yaml` 里，engine/ 与 scripts/ 全仓零引用**（`cn.yaml:13`、`etf.yaml:13`、`us.yaml:12`、`hk.yaml:13`）。
- 后果：即使跑了回测，结果既不能被产品调用，也不受涨跌停/停牌等真实约束，**与纸面成交表现不可比**——而"涨跌停买不进/卖不出"恰恰是 A股回测最大的乐观来源。

### 7.4 已有的、可直接复用的资产（不只是缺口）

| 资产 | 位置 | 对研究闭环的意义 |
|---|---|---|
| T+1 批次账本（当日买入不可卖、FIFO 扣减） | `engine/trading/broker.py:30-38,41-56,182-185` | 回测可直接复用同一套批次语义，避免"两套规则" |
| 整手取整（失败保守回退 100） | `engine/trading/risk.py:33-44,274,277` | 撮合与回测共用 |
| 费用引擎（佣金 + 印花税方向 + 滑点 + 价格精度） | `engine/trading/broker.py:59-63,97,157` | 已按市场参数化，回测可直接接入 |
| 四市场规则配置 | `config/market/{cn,etf,hk,us}.yaml` | **规则版本化的天然落点**（加"生效日期"即可支撑 §2.3） |

### 7.5 缺口清单（工程口径，可直接转 issue）

**数据层（P0）**
1. 无本地行情库：`data/` 只有 `macro/`，`runtime/data/` 只有 `portfolio.json` 与 `research/<market>/*.json`（284 B/个）→ 无任何 OHLCV 落盘。
2. 历史接口只有"末 N 根"，无日期区间：`stock-fetcher.js:877-888`（`allData.slice(-N)`）。
3. 缺字段：成交额（amount）、复权因子、停牌标记、涨跌停价：`stock-fetcher.js:182-191`。
4. 备用源口径不一致：腾讯 qfq vs 新浪不复权（`stock-fetcher.js:240-261`）。
5. `amount` 单位随市场/源不同且未归一：`stock-fetcher.js:124-145`。
6. 快照只留最新、无按日回放：`engine/screening/storage.py:197-240,265-269`。

**评估层（P1–P2）**
7. 回测无对外入口：`engine/api/server.py:119-425` 无 backtest 路由。
8. 涨跌停不可成交未实现（`price_limit_pct` 零引用）。
9. 无过户费、无最低佣金（`grep 过户费|transfer_fee|min_commission` 零命中）。
10. 无停牌不可成交判断（停牌只在回测里 forward-fill）。
11. 成本写死 0.00225，未接市场费率。
12. 无超参搜索（无空间/loss/采样器/结果索引）；组合采样 `random.expovariate` 无种子 → 不可复现（`engine/optimizer/engine.py:64-65`）。
13. 无逐笔统计（胜率、盈亏比）与基准对照的产品化输出。

**自检层（P3）**
14. 无前视偏差检验、无预热窗口敏感性检验、无规则版本标注。
